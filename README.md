# TaskSync

Кроссплатформенный менеджер задач (Windows / Linux / macOS / Android) на Python + Flet
с офлайн-работой и синхронизацией через Яндекс.Диск.

## Возможности (MVP)

- Задачи с названием, заметками, тегами, приоритетом (низкий / средний / высокий)
- Гибкая периодичность: каждые N дней, по будням, еженедельно (с выбором дней), ежемесячно
- Дедлайны и напоминания (уведомление в приложении при наступлении срока)
- Категории/проекты с цветными метками
- Подзадачи (чек-листы) с прогрессом
- Выполнение повторяющейся задачи переносит её на следующий срок и ведёт историю выполнений
- Фильтры: все / сегодня / просроченные / выполненные, фильтр по категории
- Поиск по названию, заметкам и тегам
- Тёмная и светлая тема
- Синхронизация между устройствами через Яндекс.Диск (журнал изменений, работа офлайн)

## Архитектура

```
tasksync/
  core/            # не зависит от UI и облака
    models.py      # Task, Category, Recurrence
    recurrence.py  # расчёт следующего вхождения
    store.py       # SQLite + append-only журнал изменений, LWW-слияние
    scheduler.py   # фоновые напоминания
  sync/
    base.py        # SyncProvider — интерфейс облачного провайдера
    yandex.py      # Яндекс.Диск REST API (OAuth)
    engine.py      # обмен журналами: devices/{device_id}.jsonl
  ui/              # Flet-интерфейс
tests/             # юнит-тесты (ядро, синхронизация, логика UI)
main.py            # точка входа
```

**Синхронизация.** Каждое устройство пишет только свой файл `devices/{id}.jsonl`
на Диске, поэтому конфликтов записи в облаке нет. Чужие журналы скачиваются и
применяются идемпотентно; конфликт правок одной задачи решает более поздняя
метрика времени (last-write-wins). Удаления передаются как tombstone.
Новые облака добавляются реализацией четырёх методов `SyncProvider`.

**Данные.** Локально: `~/.tasksync/tasksync.db` (можно переопределить через
переменную окружения `TASKSYNC_HOME`). На Диске: папка `TaskSync/devices/`.

## Запуск на ПК

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt   # Windows
# .venv/bin/pip install -r requirements.txt     # Linux/macOS

.venv/Scripts/python main.py        # нативное окно
.venv/Scripts/python main.py --web  # веб-версия на http://127.0.0.1:8550
```

## Тесты

```bash
.venv/Scripts/python -m unittest discover -s tests -v
```

## Настройка синхронизации с Яндекс.Диском

1. Зарегистрируйте приложение на https://oauth.yandex.ru/client/new
   - Платформа: «Веб-сервисы»
   - Доступы: `cloud_api:disk.read`, `cloud_api:disk.write` (или «Доступ к Яндекс.Диску»)
   - Redirect URI: `https://oauth.yandex.ru/verification_code`
2. Получите OAuth-токен (implicit flow), открыв в браузере:
   `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ВАШ_CLIENT_ID>`
3. В приложении: Настройки → вставьте токен → «Синхронизировать».
   На втором устройстве укажите тот же токен — данные сойдутся автоматически
   (синхронизация также запускается при старте приложения).

## Сборка под Android

Требуется Flutter SDK (`flutter doctor` должен проходить) и Android SDK:

```bash
.venv/Scripts/pip install flet[all]
.venv/Scripts/flet build apk
```

APK появится в `build/apk`. Установка: `adb install build/apk/*.apk` или передача файла на телефон.

Ограничения мобильной версии: напоминания приходят, пока приложение запущено
(фоновые уведомления Android — в плане развития).
